# Cardi-Golf sweep, 2026-09-28 (HEAD d033e38)

A full read-only pass over the app after the redesign: engine, data layer and Supabase, player screens, Comité and organizer screens, tooling and PWA, plus a visual pass over `design/shots/after`. Five parallel audits; the headline of each was re-verified by hand against the code. Nothing was changed.

Baseline: `tsc` clean, `eslint` 0 errors (7 react-refresh warnings), 149 tests green, smoke green. The tenant boundary (RLS per tournament, PIN hashing, service key only in the backup cron), the core scoring rules (§5), the outbox's optimistic overlay and the module seam are solid. The problems are concentrated in five places: **field-day resilience (offline, reconnect, sync latency), a few money/rule edge cases in the engine, destructive admin paths that are not transactional, one auth check that gives every player the Comité UI, and copy/a11y debt.**

Severity: **P0** = wrong money or lost data on a real tournament day; **P1** = fix before the trip; **P2** = improvement / cleanup. Each item names the file so the fix PR can start there.

---

## P0: wrong money, lost data, or wrong access

1. **Every PIN-linked player gets the Comité UI.** `src/data/api.ts:115` `isOrganizerOf` queries `tournament_organizers` by tournament only, and `tournament_organizers_read` (`0003_rls.sql:63`) lets any member read those rows, so it returns true for everyone; `TournamentGate.tsx:66-71` sets `isAdmin` from it. RLS still blocks the writes, so the exposure is the UI plus raw error toasts. With two organizers `maybeSingle()` errors and the real organizer is locked out. Fix: filter by `auth_user_id`, or an `is_tournament_organizer` RPC; add the case to `scripts/rls-test.mjs`.
2. **Saving groups wipes the round's snake tiebreak answers.** `replaceGroups` (`api.ts:322`) deletes and re-inserts groups; `snake_tiebreaks.group_id` cascades (`0001_schema.sql:201`). Any tee-time edit after play started reopens every "¿Quién embocó al último?" and drops queued answers as FK errors. Fix: upsert groups on `(round_id, number)` and diff members, or key tiebreaks by group number.
3. **Outbox drops a score after 20 failed pushes (~10 min) on network errors.** `outbox.ts:160-170` treats attempts ≥ 20 like a permanent error. A phone with weak signal that reports online loses holes. Fix: only drop on permanent errors; keep retrying network errors indefinitely and keep the row visibly pending.
4. **Scores queued offline are discarded if the round is finished or the card signed before they flush.** RLS rejects them (`0003_rls.sql:108`), the rejection matches `isPermanent`, the item is deleted. Fix: keep RLS-rejected score items in a "rechazados" list for the Comité, and warn in "Terminar ronda" when phones may still be syncing.
5. **Cold open with no signal shows an error screen, not the last boards.** Nothing persists the snapshot (`tournamentStore.ts:84-154`); `TournamentGate.tsx:60` needs the lookup RPC. §8 promises the last known snapshot; `t.errors.offlineFirstOpen` exists but is unused. Fix: cache `{lookup, me, snapshot}` per slug in the existing Dexie DB and enter from it when the fetch fails.
6. **Calcutta slots that cannot be filled are paid to the champion's owner as "Redondeo".** `auction/index.ts:180-194, 228-232`. The default settings ship `tiers: []` with C/D slots (20% of the pot mislabelled), and in the first tournament a three-way tie for last can move $1,800 the same way. Fix: emit unfilled slots with a warning (Comité decides), and a schema refine that every payout tier and pairing tier exists in `tiers`.
7. **"Picked-up hole counts 3 putts" never applies.** `fewestPutts/index.ts:36` uses the setting only when `putts == null`, and the Tarjeta always sends a number (`ScorecardScreen.tsx:198`, default 2). A player who picks up is charged fewer putts than one who holes out in three. Fix: `max(entered, pickupPutts)` on picked-up holes.
8. **Fewest putts ranks by raw total, so the player with the fewest holes wins.** `fewestPutts/index.ts`: a withdrawal after nine holes takes the $1,000, and live the board is led by the group furthest behind. Fix: rank only players with the maximum holes played; mark the rest.
9. **"Pagado" for Calcutta marks every lot of a multi-lot owner paid after one payment.** `money.ts:64-69` compares the aggregate paid against one flow; `setPaymentPaid` (`api.ts:440`) keeps a single row per (kind, from, to) and overwrites the amount. Fix: compare aggregate to aggregate, as the payout branch does.
10. **Restore from backup is ~20 sequential requests with no transaction.** `backup.ts:54-105` deletes everything first; one FK failure mid-way leaves a wiped tournament. It also runs before the tournament-id check and uses a native `confirm()`. Fix: a `restore_tournament(jsonb)` security-definer RPC in one transaction.
11. **Adding a round with an existing number silently overwrites that round.** `upsertRound` (`api.ts:280`) conflicts on `(tournament_id, number)` without an id; editing a round's number fails with a raw `rounds_pkey` message. Fix: insert vs update by presence of `id`, check the number client-side.
12. **PostgREST's 1000-row cap is never handled.** `tournamentStore.ts:109-119` and `backup.ts:24-29` use plain `.in()` selects. 60 players × 2 rounds = 2,160 score rows → truncated standings, money and backups with no warning (the cron pages correctly). Fix: `.range()` paging in both helpers.
13. **A new deploy reloads phones mid-hole.** `vite.config.ts:16` `autoUpdate` + `registerSW({ immediate: true })` calls `location.reload()` on activation; unsaved steppers are lost and on weak signal the reload lands on item 5. Fix: `registerType: 'prompt'` with a toast the Tarjeta defers while a draft is dirty; RUNBOOK rule "no deploys during rounds".

## P1: fix before the trip

14. **Second, third and fourth players of a hole reach the server 5 s late.** `outbox.ts:178` reschedules the rest of the queue at 5,000 ms after the first push; the chip reads "3 pendientes" on every save with good signal. Fix: loop `flush` until drained, or batch the four upserts.
15. **Boards stay stale after reconnect.** The store reloads only on a Postgres-changes event (`tournamentStore.ts:218`); nothing reloads on `online`, `visibilitychange` or a re-`SUBSCRIBED` channel; overlapping reloads have no sequence guard. Fix: reload on those three transitions, monotonic request id.
16. **"Guardar hoyo" hides behind the tab bar on short screens.** `.saveBar` sticks at `bottom: 8px` (`ScorecardScreen.module.css:146`) under the 56 px sticky tab bar (`TournamentShell.module.css:40`). Fix: offset by the tab bar height plus safe area.
17. **Wrong "Hoyo" figure in Juegos.** `GamesScreen.tsx:124,168,225` render the cross-round `totals.thru` through `t.round.thru`, so after Day 1 everyone shows "F" and during Day 2 the column shows 19–36. Same helper hard-codes 18, so a 9-hole round never shows "F". Fix: pass the active round's thru and the round's hole count.
18. **Start hole 10 breaks "Grupo puntero en el hoyo N" and the honoree's last hole.** `LiveScreen.tsx:85-90,136` use the highest-numbered played hole, not the last in play order. Fix: derive from `playOrder(startHole)`.
19. **Swipes leak through sheets in the Tarjeta.** The swipe handler wraps the whole screen (`ScorecardScreen.tsx:311`); a drag on the tiebreak sheet changes the hole, resets drafts, and the answer commits the next hole's defaults plus a tiebreak on the wrong hole. Fix: ignore swipes while any sheet is open.
20. **Course editor cannot remove a tee.** `CourseEditor.tsx:76-78` re-appends the parent's tees on render after `removeTee`; removing the last tee is undone, removing a middle one duplicates the last. Fix: lift tees to the parent, drop the render-time sync.
21. **Pending photo and pending course refs leak between flows.** `AdminCourses.tsx` clears `pendingPhoto`/`pendingCourseId` only on save; cancelling the draft leaves them armed, so the next save attaches the photo to, or overwrites, another course. Fix: clear on cancel/close.
22. **Hammer after a failed sale opens the buyback sheet for an unsold lot.** `AdminAuction.tsx:146-154`: `run()` swallows errors. Fix: only open buyback on success. Also the hammer sells to the player himself even when he is at the owner limit.
23. **Draw of 14+ pairs writes "09:60" tee times.** `AdminDraw.tsx:90` after pairs are already saved, so Day 1 groups are lost. Fix: reuse `withTimes`, do pairs + groups in one RPC.
24. **Comité tiebreak answers go through the outbox with no error path.** `AdminScores.tsx:202` toasts "Guardado" before the push; a server rejection is silent. Fix: direct upsert with `unwrap` like every other admin mutation.
25. **Comité score edits have no client validation.** Empty strokes → 0, putts > strokes → raw Postgres check errors. Fix: validate like the Tarjeta with `t.card` copy.
26. **Admin players cannot create courses or scorecards.** `courses_insert` and the storage policy require a non-anonymous user, but the Comité shows the buttons (RUNBOOK says Nico runs the Comité with a PIN). Fix: allow `is_admin` players, or hide the actions with a Spanish explanation. Deleting another organizer's course also fails silently (0 rows, no error).
27. **Money "si terminara ahora" pays everyone before a single score.** `individual/index.ts:96`, `pairs/index.ts:325` split prizes over the all-tied field; on Calcutta night Dinero shows twelve T1 rows with $1,667 each and a $7,000 banker gap (visible in `minimal4-setup--live.jpg`). Fix: no prizes and no `lastPlace` until a hole is played.
28. **Admin can overwrite a signed card from the Tarjeta with no reason.** `ScorecardScreen.tsx:148` `canEdit = me.isAdmin || …` bypasses the §7 reason rule. Fix: route to Comité › Tarjetas or ask for a reason.
29. **PIN lockout never resets and enables trivial lockouts.** `0002_functions.sql:300`: after the 5-minute lock `failed_attempts` stays at 5, so one more wrong digit locks again; any visitor can lock all players out from Entrar. Fix: reset when `locked_until` has passed; count per `auth.uid()` as well.
30. **Comité `reason` on scores is sticky and player-settable.** `0009_score_reason.sql:12-16` treats a non-null reason as authoritative and the column is never cleared; `scores_write` restricts no columns, so a player can send `reason` or `disputed:false`. Fix: require `reason is distinct from old.reason` and organizer rights in the trigger.
31. **Unbalanced prize pool can be saved from Torneo** (`AdminTournament.tsx`: only `parsed.success` gates save; the wizard blocks it); the check uses a hard-coded 12 when no players exist; name/tagline/accent never resync after a realtime change. Fix: block save on `!balanced`, persist the expected player count.
32. **Status transitions are unguarded.** Any status jump in Torneo; "Iniciar ronda" needs no groups and steals `current_round_id` from a live round; "Reabrir" a cancelled round goes straight to live (`AdminRounds.tsx:58`).
33. **`/api/scorecard-extract` and `/api/course-search` are unauthenticated and unthrottled.** Anyone can burn the Anthropic balance and provider quotas; `mediaType` is forwarded unvalidated; Vercel's 4.5 MB body limit returns a platform 413 before the route's Spanish error for larger PDFs. Fix: require a Supabase access token (non-anonymous), rate limit, cap the payload client-side.
34. **Deleting a player or a tee cascades silently.** Player delete removes his pair (and its signatures), payments including banker legs, lots and scores behind a generic confirm (`AdminPlayers.tsx:126`). `saveCourse` tee removal cascades `round_tees` and nulls `default_tee_id` across every tournament sharing the course (`api.ts:234`). Fix: name what goes; block once referenced.
35. **Cut compounds for rounds 3+** (`compute.ts:112-120`), undefined by §5.2; make it a setting or document it.
36. **9-hole rounds get ~60% too many strokes** (`compute.ts:139` passes `round.holes` into the allocation). Latent until a 9-hole round exists.
37. **Snake, stats and the Tarjeta index holes by array position** (`snake/index.ts:74` etc.); a tee with a missing hole shifts everything silently. Look up by hole number.
38. **Share image on iOS** rejects with `NotAllowedError` after the async render and shows "No se pudo generar" instead of falling back to download (`shareImage.ts:12`); fonts are not awaited. Also the pairs board's money chip is clipped ("$2,0", `full12-live--juegos--los-matrimonios.jpg`).
39. **`public._migrations` has no RLS** (created by `scripts/db.mjs`): readable and writable with the publishable key, including inserting a filename to skip a migration. `lookup_tournament` runs without a session and returns every player's full name and the join code by slug alone.

## P2: improvements and cleanup

**Field-day UX**
- Undo toast after saving a hole only navigates back; nothing is undone (`ScorecardScreen.tsx:212`). Relabel or really re-enqueue the previous values.
- Tiebreak buttons ignore `busy` (double tap = duplicate writes). Raw PostgREST English errors appear under "Guardar hoyo" and in `unwrap` toasts; `pending` counts every tournament's items.
- "Sin señal" in the shell reflects the Realtime channel, the Tarjeta chip reflects `navigator.onLine`; they can contradict.
- The Tarjeta shows "3 pts, birdie neto" in red for unsaved default values on every player before anything is entered (`full12-live--tarjeta.jpg`); consider muting the badge until a value changes.
- `roundNotLive` copy shows for a finished round between days.
- Logo and avatars are not cached offline (no Workbox `runtimeCaching` for Supabase Storage).
- Dev routes (`/design`, `/t/_/<fixture>`) ship to production with real player names and fixture admins; gate them on a preview-only flag.

**Engine and money**
- Prize-pool check assumes uniform group size (`prizeCheck.ts:30`): 11 players balance at setup and miss by $400 at the end.
- Unsold lot at `tournamentFinal` cashes as self-owned with `paid: 0`; should warn.
- Explanation strings: `6.666666666666667%`, "Día ${roundIds.length}" mislabels after a cancelled round, hard-coded "hoyo 18" and "3-putt", "5 ÷ 2 = 2 golpes", " · " and "→" joins still surface in Dinero, Jugador and Ceremonia (already logged), best round and pairs have no tie explanation.
- Tests: no 9-hole, >2 rounds, groups of 2–3, DNF, `tiers: []` with auction, multi-lot `isPaid`; `games.test.ts:62-68` pairs assertions sit inside a conditional and can assert nothing; `handCalc.test.ts:448` asserts the pick-up bug as intended.

**Comité and organizer**
- Sheets close on backdrop/Escape and discard the player form or a just-read scorecard draft with no confirm (Grupos has the guard).
- Avatar uploads on pick, before save, to a random path; orphans on cancel.
- Wizard: switching template resets "Ajustar reglas" edits; browser Back leaves the wizard.
- Manual tees are always 18 holes; start-hole options are 1/10 only; `pasteError` hard-codes "18"; no 9-hole card is possible.
- `drawGroupsFromPairs` with no tiers makes groups of two regardless of `groupSize`.
- Provider adapters silently fabricate SI 1–18 / par 4 when missing and the review draft says nothing; `mergeHits` can absorb a course-level hit into its club.
- Join code is generated client-side with no uniqueness check although `generate_join_code()` exists.
- "Duplicar" does not copy PINs, pairs, groups or banker; the hint should say so. `setPaymentPaid` is select-then-insert (double tap = duplicate rows).
- Hard-coded strings outside `es-MX.ts`: `> $250`, `(copia)`, `${place}º lugar`, `(damas)`, `Par`/`hoyos`, `{delete} tee`, grid headers in `primitives.tsx` ("Vta" vs "Vuelta"), " y ", " contra ", " & ", " + ", English `aria-label`s on score marks.

**Copy**
- `stats.noData` uses "scores" and "stats" (banned terms); "o más más recientemente"; "código de seis letras" (codes include digits); yards render as "380 y"; ties read "T3º"; `whoHoledLastHint` hard-codes 3 putts; Reglamento prints "Parejas fijas por categorías ()" with no tiers.
- RUNBOOK/README/handoff still name "Scores", "Stats y premios", old button labels, the vercel.app URL and an expired token date; `design-shots.mjs` waits 30 s for the old "Toca tu cara" text.

**Accessibility**
- No `MotionConfig reducedMotion="user"`; leaderboard re-sorts, TV transitions and the snake slide ignore the preference.
- `Sheet` has no focus move, restore or trap; nested sheets share one Escape and reset body scroll early; title-less sheets have no accessible name.
- Board rows are buttons whose name is a concatenation of figures; `Segmented` is a fake tablist for view toggles.
- Targets: `.btn--sm` 36 px on the most-tapped controls, stepper columns 40 px, hole and grid cells 36 px; clickable `<tr>` in Estadísticas without keyboard access.
- `.locked { opacity: .55 }` and `--ink-3` on `--surface` (4.3:1) fall below AA; disabled ghost buttons take a grey fill that reads like an enabled secondary button (login screen).
- `maximum-scale=1` blocks pinch zoom; `orientation: portrait` locks an installed tablet out of landscape TV.

**Layout**
- `/imprimir` prints inside the 560 px column with ~24 px cells and no `@page`; the last card leaves a blank page; the date is raw ISO.
- Shell bottom padding plus the tab bar's own safe-area padding leaves a floating strip under the tab bar at full scroll.
- Player sheet scorecard clips at hole 8 with no scroll affordance; Ida/Vuelta cells stack two unlabelled numbers (points over gross).
- TV shows the top 12 and clips the rest; no wake lock.
- Estadísticas "varianza 1.641" and similar long units crowd the award row.

**Tooling**
- Pre-push guard matches only the literal `git push` in Bash; the GitHub write tools in the `allow` list bypass it; no git-level hook. Move `push_files`/`create_or_update_file`/`delete_file` to `ask`, match `git\b.*\bpush\b`, install a real `pre-push` hook.
- `.env.example` is missing most server-side names; `design-organizer.mjs` reads `SUPABASE_SERVICE_ROLE_KEY`; the copied `.env.local` parser rejects names with digits (`R2_*`).
- `e2e/smoke.mjs` takes any `E2E_SLUG` with no `ensayo` guard although it mutates data.
- CI runs `check` twice per PR; five `exhaustive-deps` suppressions hide real deps; `e2e/` is unlinted.
- `design/shots` is 58 MB of committed JPEGs; consider LFS or keeping only `after`.
- Simulator nits: Day-1 points computed against the current round's tees; clamped putts still create tiebreak rows.
